# SoundCraft-AI capability matrix

**Task:** P0-T02 in the [execution plan](execution-plan.md) · **Spec:** PRD v0.3 §3.1–§3.2
**Matrix version:** 0.1 · **Updated:** 14 October 2026 · **Status:** Source pass complete; every runtime column is unverified.

This matrix records, for each foundation capability the PRD depends on, three independent kinds of
evidence (PRD §3.1):

- **Documented:** what the repository's docs say, with the doc's own review date. Where docs and
  source disagree, the doc is historical evidence only.
- **Source-inspected:** what the code at the pinned commit actually does, with file and line.
  Existing automated tests are listed here as source evidence. They were **not run** in this pass,
  and passing unit tests is not runtime qualification.
- **Runtime-tested:** a result measured on the packaged app on the reference host. Every row starts
  as *Unverified*; the named Phase 0 task fills it in.

A passing entry needs an evidence link and a date (PRD §15).

## Detail

### 1. Disk recording (PRD S7, S13, S14)

- **Documented:** `docs/hardware-parity.md:28` (reviewed 2026-10-10): "❌ recording into RAM (PR #84)".
  **Stale.** PR #84 ("Record takes straight to disk", merge `ef04444`, 2026-10-12 AEDT) is an
  ancestor of `6cf896e` (`git merge-base --is-ancestor` succeeds). The PRD's v0.2 RAM-only baseline
  came from this line.
- **Source-inspected:** `crates/playback/src/record.rs`
  - Opens `host.default_input_device()` only (`:96`). FreeBSD returns "not supported on this
    platform yet" (`:137`).
  - The input callback pushes into a lock-free single-producer, single-consumer ring of
    `RING_SECONDS = 4` (`:19`, `:23-58`). Samples that don't fit are counted in `dropped`
    (`:63-74`).
  - A writer thread streams one WAV file per take and rewrites the header every second
    (`:179`, `:191-193`).
  - `finish()` returns the takes and the first problem met: a writer error, or "N ms of input lost:
    the disk was too slow" (`:162-168`, `:197-207`).
  - Tests: 6 unit tests in `record.rs`.
- **Open for runtime (P0-T04):** errors appear to surface only when `finish()` is called; whether
  the user sees a writer error or overflow *during* a take is not established. Also open: playable
  length after `kill -9`, disk full, file-creation failure, ring overflow, and source linking. A
  one-second header rewrite doesn't by itself prove G09's ≤ 1 s loss (PRD §6.6).
- **Runtime-tested:** Unverified.

### 2. Input and output devices (S7, S10)

- **Documented:** `docs/hardware-parity.md:19-20`: "default output only" and "default input only
  (#42)". `docs/gaps.md` G-01 estimates device selection at about 25–40 h.
- **Source-inspected:** `crates/playback/src/lib.rs:714-717` (`open_device` →
  `host.default_output_device()`) and `crates/playback/src/record.rs:96`
  (`default_input_device()`). `setup.playback_engine` stores `device` and `buffer_size`, which
  playback ignores (per gaps.md G-01).
- **Runtime-tested:** Unverified (P0-T05).

### 3. Processing block (S10)

- **Documented:** `docs/hardware-parity.md:21`: "fixed 512-sample mix block". **Incomplete**, as
  PRD §3.2 notes.
- **Source-inspected:** `crates/playback/src/lib.rs`
  - `BLOCK = 512` (`:36`) is the maximum.
  - The render quantum is `ceil(callback_frames × rate step)` clamped to 1..=512 (`:270`), and
    each render step is clamped the same way (`:200`). Smaller device callbacks therefore render
    smaller quanta.
  - Plugins are instantiated with a `BLOCK` maximum (`:683`).
  - Tests: 8 unit tests in `playback/src/lib.rs`.
- **Open for runtime (P0-T05):** actual callback sizes on the named interface, round-trip latency
  and alignment. Don't estimate the round trip as twice the maximum block (PRD §12.1).
- **Runtime-tested:** Unverified.

### 4. Session revision (S8, S9)

- **Documented:** no revision field in `docs/control-protocol.md` or `docs/mcp.md`.
- **Source-inspected:** `crates/engine/src/lib.rs`
  - `pub revision: u64` (`:113`) starts at 1 in `Engine::new` (`:146`).
  - `wrapping_add(1)` on every `session_mut` (`:164`), so **selection changes bump it**, because
    the selection lives in `Session.edit` (`crates/engine/src/cmd/edit.rs:58-68`). Zoom does not
    (`:169-173`).
  - Also bumped on replace, undo, redo and rollback (`:184`, `:227`, `:236`, `:278`, `:297`).
  - `replace_session` increments the counter rather than resetting it within a process, but a new
    process starts at 1 again. That's why an instance ID is needed (plan P1-E01).
  - `session.inspect` (`crates/ui-egui/src/control.rs:119`, `crates/engine/src/inspect.rs`) does
    not return it.
- **Runtime-tested:** Unverified (P0-T06 audits the bump semantics).

### 5. Undo and snapshots (S8)

- **Documented:** `docs/architecture.md:35-39`: each command pushes an undo snapshot (the previous
  `Arc<Session>`) when the document changed.
- **Source-inspected:** `crates/engine/src/lib.rs`
  - `HistoryEntry { label, doc: Arc<Session> }` (`:94-97`), `history_limit: 200` (`:140`).
  - `execute` restores the document when a command returns an error (`:293-301`) or panics
    (`:276-281`).
  - `push_undo` (`:242-252`) and `execute_merged` gesture coalescing (`:317-327`).
  - History is cleared on `replace_session` (`:182-183`).
  - Tests: 2 unit tests in `lib.rs`; property tests in `crates/engine/tests/random_edits.rs`.
- **Open for runtime (P0-T06):** state that lives outside `Session` (`transport_requests`, plugin
  instances in the player, the source pool) and how the renderer picks up a new `Arc<Session>`.
- **Runtime-tested:** Unverified.

### 6. Batch commands (S2, S3)

- **Documented:** `docs/mcp.md:25`: `batch` runs commands in order. With `keep_going`, later
  calls still run after a failure. The desktop protocol (`docs/control-protocol.md`) has no command
  batch. The "validated transaction" at `:100` refers to `ui.dock` layout operations, not engine
  commands.
- **Source-inspected:** `crates/automation/src/mcp.rs:133` loops over the calls in order with no
  rollback. JSON-RPC array batches (`:253-254`) are handled the same way. Tests: 0 in `mcp.rs`;
  agent tasks in `crates/automation/tests/agent_tasks.rs`.
- **Consequence:** not an atomic commit (PRD §7.2); replaced for the assistant path by P1-E02.
- **Runtime-tested:** Unverified.

### 7. Local control (S3, S16)

- **Documented:** `docs/control-protocol.md:29`: newline-delimited JSON over TCP on `127.0.0.1`.
  No authentication is described.
- **Source-inspected:** `apps/soundcraft/src/control_server.rs` binds `127.0.0.1:<port>` (`:13`).
  `serve` (`:36-49`) parses each line's `method` and forwards it to the UI thread with no
  credential check. The UI side exposes `engine.execute` for any command, plus `ui.click`,
  `ui.key` and other input injection (`crates/ui-egui/src/control.rs:5-13`). Tests: 0 in
  `control_server.rs`.
- **Consequence:** any local process can drive the app. This is a transport, not an authorisation
  boundary (PRD §10.2); fixed by P1-E03.
- **Runtime-tested:** Unverified (P0-T07 writes the rejection tests).

### 8. Audio to MIDI (S11, S15)

- **Documented:** `docs/target-app-parity.md:91` calls it "an audio-to-MIDI pitch tracker".
- **Source-inspected:**
  - `crates/dsp/src/pitch_detect.rs:14`: `yin(...) -> Option<f32>`, one estimate per frame with
    no confidence value.
  - `:67`: `audio_to_notes` returns `DetectedNote { start, end, pitch: u8, velocity }`, so pitch is
    rounded to MIDI semitones and segmented.
  - Command `edit.copy_audio_as_midi` (`crates/engine/src/cmd/audio_midi.rs:12`).
  - Tests: 3 in `pitch_detect.rs`, 1 in `audio_midi.rs`.
- **Consequence:** a candidate input aid, not a confidence-bearing continuous contour (PRD §6.3).
  It is the baseline in the P0-T08 benchmark.
- **Runtime-tested:** Unverified.

### 9. Backing import (S2)

- **Documented:** `docs/mcp.md:28`: `import_audio` accepts WAV, AIFF, FLAC, MP3, OGG, AAC/M4A, ALAC
  and CAF. `docs/file-format-parity.md:41-42`: MP3 and AAC/M4A import ✅ via symphonia.
  `docs/hardware-parity.md:65`: whole files are decoded into the `SourcePool`, with no disk
  streaming.
- **Source-inspected:**
  - `Cargo.toml:39`: symphonia 0.5 with `mp3`, `aac`, `isomp4` and other features.
  - `crates/audio-io/src/symph.rs:41`: `FormatOptions { enable_gapless: true }`, so symphonia
    trims encoder delay and padding **where the container declares it**.
  - Tests: none in `symph.rs`. `crates/audio-io/tests/{roundtrip,encode_format,malformed}.rs`
    mention these formats; what they assert hasn't been checked yet.
- **Open for runtime (P0-T03):** decoded onset offset for LAME-tagged and untagged MP3, MP3 VBR,
  and AAC-LC in M4A with and without iTunes gapless metadata; channel mapping; save and reopen
  persistence; corrupt files.
- **Runtime-tested:** Unverified.

### 10. Built-in processors (S5, S12)

- **Documented:** `docs/plugin-parity.md:16-17` lists `eq_1band`, `eq_7band`, `channel_strip` and
  `compressor`. `:32`: "Fidelity: **unmeasured**", measured against Pro Tools there. The PRD
  qualifies against declared behaviour instead.
- **Source-inspected:**
  - `crates/dsp/src/plugins/eq.rs:129` (`Eq<S>`), with response functions `eq7_response` and
    `eq1_response` (`:306`, `:311`).
  - `crates/dsp/src/plugins/dynamics.rs:59` (`Compressor`).
  - Tests in `crates/dsp/tests/plugins.rs`: `eq_magnitude_at_center_matches_gain` (`:179`) and
    `compressor_steady_state_gain_reduction` (`:203`).
  - The mixer renders strips in parallel with rayon (`crates/mix/src/lib.rs:1125-1129`), which
    agrees with PRD S12. Summation order and determinism are still to be tested (G05).
- **Runtime-tested:** Unverified (qualified in P1-M02, P2-M01, P2-M02).
